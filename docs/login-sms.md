# 登录流程中的短信身份验证

小红书可能在首次扫码、二次扫码之后要求短信验证码。服务只识别官方网站的验证弹窗，并在用户明确提供验证码后通过同一页面提交，不读取短信、不发送新短信，也不自动猜测或重试验证码。

1. 调用 `get_login_qrcode`，展示登录二维码。
2. 用户扫码后调用 `check_login_status`。若返回二次身份验证图片，展示新图片让用户扫码，再检查状态。
3. 状态为 `sms_required` 时，将短信提示中的脱敏手机号展示给用户，索取本次短信验证码。保留响应中的 `session_id` 和 `verification_id`。
4. 调用 `submit_login_sms_code`，提交当前会话编号、验证标识和用户提供的验证码。验证码必须是字符串，以保留开头的 `0`。
5. `sms_submitted` 只代表已提交，继续调用 `check_login_status`。只有 `is_logged_in=true`／明确已登录结果才代表网页登录完成并保存 Cookie。

HTTP 等价接口：`POST /api/v1/login/sms`，请求头仍需携带服务的 Bearer Token，请求体字段为 `session_id`（整数）、`verification_id`（字符串）、`code`（4 至 8 位数字字符串）。敏感验证码放在请求体，不能放在 URL 查询参数中。

状态接口的补充状态：

| 状态 | 行为 |
| --- | --- |
| `sms_required` | 等待用户提供本次短信验证码；不会新建二维码或新浏览器。 |
| `sms_submitted` | 已向网页提交，等待结果；不要重复提交。 |
| `sms_error` | 网页提示验证码校验失败或过期；告知用户，不自动重试。 |

首次发现短信验证时提供新的 4 分钟会话等待窗口；重复检查不会无限延期。这是浏览器会话的等待时间，不代表短信验证码的有效期。

`verification_id` 随当前短信验证会话随机生成。登录重置、服务重启或会话过期后，旧验证标识不能用于另一个会话。同一会话内，同一个验证码最多提交一次，未知结果同样不自动重试。验证码错误时，只提交用户重新明确提供的不同验证码。会话失效时从登录流程重新开始。

服务响应和业务日志不回显验证码。MCP 客户端也应避免将验证码写入长期记忆、调试日志或持久化工具记录；其记录策略由客户端管理。
